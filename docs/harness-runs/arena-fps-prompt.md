Задача: с нуля написать в этой папке (ArenaFightFPS) игру «Арена Битвы FPS» на Godot 4.7.2 — аренный шутер от первого лица с ботами для Яндекс Игр. Работаешь автономно и долго: я не отвечаю на вопросы во время работы, решения принимай сам по ТЗ.

0. Это большая автономная задача: сначала вызови create_goal («Полностью сделать игру по SPEC.md: все пункты плана выполнены, проверены и закоммичены»). Загрузи навык godot (skill) — там путь к движку, проверки, скриншоты и правила GDScript.
1. Прочитай SPEC.md целиком — это ТЗ и правила, которые нельзя нарушать.
2. Изучи референсы в referens/: посмотри скриншот (read_image). Видео большое (≈830 МБ) — нарежь из него 6–10 кадров в разные моменты ffmpeg'ом (он есть: <путь к ffmpeg.exe>, кадры клади в referens/frames/) и посмотри их. Кратко запиши в NOTES.md, что ты увидел в референсах (только то, что реально видно на картинках) и какие решения из этого следуют для нашей игры.
3. Составь план в todo_write: от каркаса к полной игре. Порядок: проект и tools/check.tscn → игрок (движение, скольжение, выносливость, перелезание, стрельба) → карта и окружение → боты → матч TDM и HUD → остальные режимы → серии (радар, FPV-дрон, штурмовик) → меню и лобби → арсенал/магазин/кейсы/пропуск/задания → сохранения и мост Яндекса → звук → английский язык → сенсорное управление. Обновляй todo после КАЖДОГО выполненного пункта.
4. Работай маленькими шагами. После КАЖДОГО значимого шага:
   - запускай проверку компиляции: & "<путь к Godot_v4.7.2-stable_win64_console.exe>" --headless --path . res://tools/check.tscn — должно быть "checked N" без ошибок;
   - когда появится сцена, которую можно увидеть, — делай скриншоты (свой tools/shot_map.tscn или аргументы autostart/autoshot в main.gd) и смотри их через read_image; если видно что-то сломанное — чини, а не описывай.
   Не пиши «готово», пока не увидел это сам в выводе Godot или на скриншоте.
5. Имена API Godot бери из индекса %USERPROFILE%\.dsh\knowledge\godot-4.7.2-api.txt (grep), поведение — из документации (web_search site:docs.godotengine.org, потом web_fetch). Не выдумывай и не читай исходники движка. Мост Яндекса проверить можно только в браузере: делай его по документации с заглушкой вне веба и иди дальше.
6. Пиши заметки для продолжения работы в AGENTS.md в корне проекта: как запускать, что сделано, что проверено, что нет, известные проблемы. Обновляй его по ходу — контекст будет сжиматься, AGENTS.md и todo — твоя память.
7. Первый git commit — как только каркас проходит проверку; дальше коммит после каждого рабочего этапа, с понятным сообщением на русском. После крупных этапов (игрок, боты+матч, меню) — навык review по изменениям этапа.

Песочница разрешает запись только внутри папки проекта: скриншоты и прочие файлы проверок сохраняй в res:// (например res://_shots/, он уже в .gitignore), а не в user://.
Общайся и пиши комментарии в коде на русском.
Начинай.
